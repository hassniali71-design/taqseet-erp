# الحالة الحقيقية دلوقتي — المرجع الوحيد "وصلنا لفين"

**آخر بند: 58** (بند 58: السبب الحقيقي لاختفاء نص كروت `LabeledValue` عند الزوم —
`min-width:0` التلقائي لعناصر Grid/Flex بـ`overflow-hidden`، اتصلح بـ`min-w-fit`).
كل الوحدات متصلة بـSupabase حقيقي — مفيش Mock/localStorage في أي مسار بيانات حي.
`src/lib/data-store.ts` القديم بقى Legacy (مش مصدر بيانات فعلي) — أي كود جديد يتبع نمط
`src/lib/supabase-queries.ts` (useTenantList / insertAuditLog / nextTenantCode أو
insertWithGeneratedCode / mutations) — ده النمط المعتمد الوحيد.

**متصل فعليًا وحقيقي 100%:** الهوية (Auth حقيقي + RLS)، العملاء، المنتجات/المخزون (سيريال+حركة
مخزون)، المبيعات النقدية، التقسيط الكامل (خطط/عقود/تحصيل/وعد/تسوية مبكرة/إعادة هيكلة/إلغاء)،
الموردون والمشتريات، الخزينة/الورديات/المصروفات/المحاسبة، المرتجعات/الاستبدال/التوصيل/الضمان،
لوحة التحكم/التقارير/الإشعارات، `/users`، `/platform` (غرفة تحكم المنصة)، فيتشر **الشركاء**
(دفتر منفصل تمامًا عن الخزينة — migration 0014+)، تنبيهات SMS/WhatsApp عبر Twilio (تحتاج مفاتيح
حقيقية من المستخدم ليست مفعّلة حاليًا)، استرجاع كلمة السر الحقيقي (Supabase Auth + SMTP).

**أمان (بند 53 أصلحه):** كل دوال السيرفر (`getSupabaseAdmin`) بتتحقق فعليًا من هوية المستخدم عبر
`resolveServerCaller`/`assertPlatformOwner` (`src/lib/supabase-admin.ts`) — مفيش دالة سيرفر
بتثق في `tenantId`/`actorUserId` جاي من العميل بدون تحقق.

**أرقام المستندات (بند 49/52):** كل كود/رقم مستند (عملاء/منتجات/موردين/شركاء/فواتير/عقود/إيصالات
/مشتريات/مرتجعات/استبدال/قيود) بيتولّد من عدّاد ذري حقيقي (`tenant_code_counters` +
`next_tenant_code_counter()` — migration 0022/0024)، مش `COUNT(*)` — كان فيه باگ حقيقي هنا
(تكرار كود بعد حذف عميل) اتصلح جذريًا.
