# تقسيط — ERP SaaS لمحلات الأجهزة الكهربائية

نظام ERP SaaS متعدد المستأجرين (Multi-Tenant) لمحلات بيع الأجهزة الكهربائية والمنزلية في مصر، محوره البيع بالتقسيط: التزامات ائتمانية، محرك تمويل، تحصيل، مخزون بسيريالات، مشتريات وموردين، خزينة ومحاسبة، وSaaS Control Center لإدارة المحلات المشتركة.

واجهة عربية RTL بالكامل.

## المرجع الكامل

- [`docs/ERP_SaaS_Requirements.md`](docs/ERP_SaaS_Requirements.md) — المواصفة التقنية والتجارية الكاملة (134 قسم)، المرجع الملزم الوحيد.
- [`CLAUDE.md`](CLAUDE.md) — سياق العمل والحالة الحالية لأي جلسة تطوير قادمة.

## الستاك

TanStack Start · React 19 · TypeScript · Tailwind CSS v4 · shadcn/ui · TanStack Query/Router · Vite · Bun · Cloudflare Workers · Supabase (Auth/Postgres/RLS/Storage) · Zod.

## التشغيل

```bash
bun i
bun run dev
```

افتح `http://localhost:8080` — لو مفيش جلسة نشطة هتتوجه تلقائيًا لصفحة `/login`.

### بيانات الدخول التجريبية (Mock)

```
owner@demo.local / owner123
```

⚠️ هذه بيانات Mock بحتة (تخزين محلي في `localStorage`، بدون تشفير وبدون Supabase Auth حقيقي) لأغراض التجربة المحلية فقط — راجع `CLAUDE.md` قبل الاعتماد عليها في أي شيء إنتاجي.

## الشاشات المتاحة الآن

- `/login` → `/dashboard` — دخول Mock (بيانات تجريبية أعلاه)، أرقام حقيقية (عدد عملاء/أجهزة).
- `/customers` — قائمة عملاء + إضافة/تعديل + حد ائتمان (بدون حذف — إيقاف/تفعيل فقط).
- `/products` — قائمة أجهزة/منتجات بالمخزون الحقيقي + إضافة/تعديل (بدون حذف — إيقاف/تفعيل فقط).
- `/products/$id` — تفاصيل الجهاز: السيريالات وحالاتها، استلام كمية جديدة، سجل حركة المخزون.
- `/stock-count` — جرد المنتجات غير المرتبطة بسيريال.
- `/customers/$id` — Customer 360 (إجمالي مشتريات، حد ائتمان ومستحق حاليًا، ضامنون، سجل فواتير، عقود تقسيط).
- `/sales/new` — بيع نقدي (POS): عميل + أصناف (بسيريال أو كمية) + خصم محدود بحد الموظف → فاتورة.
- `/sales/$id` — إيصال فاتورة بيع.
- `/sales/new-installment` — بيع بالتقسيط: عميل مسجّل + Credit Check فعلي + مقدّم + خطة + معاينة الجدول → عقد.
- `/contracts/$id` — تفاصيل عقد تقسيط: جدول الأقساط، تحصيل دفعة، تسوية مبكرة، إعادة هيكلة، وعد بالدفع.
- `/collections` — مركز التحصيل: كل العقود المفتوحة مع القسط القادم وحالته (قادم/مستحق/متأخر)، تحصيل مباشر.
- `/users` — عرض المستخدمين + إنشاء مستخدم بدور + تفعيل/تعطيل.
- `/audit` — سجل عمليات النظام (للقراءة فقط).
- `/settings` — إعدادات المحل (عملة، طريقة تكلفة، حدود خصم/مقدم/ائتمان، فترات سماح، خطط التقسيط).

## الحالة

**Phase 0 (تأسيس) + Phase 1 (Foundation) + Phase 2 (Products & Inventory) + Phase 3 (Customers & Sales) + Phase 4 (Installments) — منفّذة، مبنية على Mock data-store.** سكافولد تقني كامل + تدفق دخول وهمي + شاشات المستخدمين/الإعدادات/سجل العمليات + مخزون وسيريالات فعليين (§21/§29/§30) + بيع نقدي فعلي بفواتير مرقّمة تلقائيًا وخصم من المخزون تلقائيًا (§32/§34) + عملاء بضامنين وسجل مشتريات حقيقي (§14/§15) + **محرك تقسيط فعلي بالكامل** (§35-§57): محرك تمويل مُختبر مقابل مثال قبول الـSpec، بيع بالتقسيط بـCredit Check حقيقي وSnapshot للخطة وقت الإنشاء، تحصيل بتوزيع أقدم-قسط-أولًا وإيصالات مرقّمة تلقائيًا، مركز تحصيل مركزي، وعد بالدفع، تسوية مبكرة، وإعادة هيكلة بدون حذف أي جدول قديم. قاعدة البيانات الحالية Mock مؤقت (`localStorage`) ريثما تتوفر بيانات اتصال Supabase حقيقية — لن تُعتبر أي مرحلة "جاهزة للإنتاج" قبل ذلك. راجع `CLAUDE.md` لخطة التنفيذ الكاملة (كل الـPhases 1→9) والحالة التفصيلية.
